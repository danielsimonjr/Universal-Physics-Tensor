## Goal

Ship **v0.7.0** as the **Intelligent Index foundation release**:
introduce a UPT-level identity-bearing index type
(`UniversalIndex<Axis>`) plus a wrapper (`LabeledTensor`) over the
existing `TensorEngine` einsum surface, so that physics-axis
identity, name, and metadata are carried alongside every engine-level
tensor without altering the engine compute contract. Three
interlocking themes:

1. **Capture physics-axis identity at the wrapper level.** UPT
   already has labeled indices on the AST side (`TensorSymbolNode.indices`,
   `freeIndices` Maps — `src/dimensional/tensor.ts:30-87`,
   `src/dimensional/validator.ts:122-152`), but they are *string-equality
   based and scoped to a single AST validation*. They carry no
   persistent identity across catalog entries: two bridges that both
   contract a "scale-quantum" axis use the string `'μ'` (or whatever
   the bridge author chose) with no enforced registry link. Proposal 1
   introduces that registry.

2. **Wrap engine-level tensors with axis-tagged metadata.**
   `LabeledTensor` composes an `EngineTensor` (the opaque handle from
   `src/numerical/tensor-engine.ts:22-24`) + a `TensorEngine` + a
   `Labels: Record<string, UniversalIndex<AxisName>>` map.
   `contract(other)` matches by **`UniversalIndexId` identity**, not
   by einsum-string coincidence. The engine call itself is unchanged.

3. **Establish the wrapper as the catalog-facing surface, NOT the
   AST-facing one.** The dimensional layer's existing labeled-index
   system stays intact in v0.7.0. The Intelligent Index layer sits as
   an **adapter** between AST free indices and engine positional axes
   — it does not subsume either. This reconciliation is the most
   important decision in this proposal (Decision #1).

**Non-goals** (deferred to v0.8.0+ or later):

- Replacing `TensorSymbolNode.indices` with `UniversalIndex` references
  (the breaking-refactor variant of reconciliation — would re-classify
  proposal as High risk; deferred unconditionally).
- Bulk migration of all 42 v0.6 bridges to `Axes` registry. Proposals
  doc §2.4 lists this as acceptance; v0.7.0 narrows to **one**
  representative bridge in Phase 4.
- ITensor's QN-aware index sectors (Section 8.2). UPT's physics-axis
  identity does NOT generalize to U(1)/Z_n-conserving block-sparse
  storage in v0.7.0.
- The `tools/migrate-strings-to-indices.ts` codemod (proposals doc §2.4).
  Deferred alongside bulk migration.
- **`prime` mark and `arrow` direction fields** on `UniversalIndex`.
  **UNVERIFIED**: the brief that pointed this designer at Proposal 1
  mentions "name, dimension, prime mark, and arrow (per the ITensor
  design)," but proposals doc §2.2 itself does NOT include prime or
  arrow on the sketch (`id`, `axis`, `name`, `tags`, `limits`, `notes`
  only). See Decision #2.
- Replacing einsum-string-based contraction inside the engines. They
  stay positional; the wrapper is the identity layer.
- Compile-time axis-mismatch detection via template-literal types
  (Decision #7 — v0.7.0 ships runtime detection; compile-time is
  v0.8.0+ research).

## Architectural Decisions (locked)

### Decision #1 — Intelligent Index is an **adapter on top** of the existing dimensional + engine layers

The architecturally pivotal decision. Three plausible relationships
between the Intelligent Index layer and UPT's existing labeled-index
system (`TensorSymbolNode.indices` + `computeContraction` +
`freeIndices`):

| Shape | Description | Effort | Risk |
|---|---|---|---|
| (A) Adapter | New `LabeledTensor` wraps `EngineTensor`; AST unchanged; bridging at the evaluator surface only. | 2-3 wk | Low |
| (B) Unified | `TensorSymbolNode.indices` rewired to reference `UniversalIndex` objects; `computeContraction` learns axis identity. | 5-8 wk | High |
| (C) Parallel | Two independent index systems coexist forever; wrapper does NOT consult AST's free indices. | 2-3 wk | Low technically; long-term coherence debt. |

**v0.7.0 locks shape (A).** `TensorSymbolNode.indices` stays as
defined in `src/dimensional/tensor.ts:30-34` (no rewiring).
`computeContraction` stays as the AST-layer primitive
(`src/dimensional/tensor.ts:182-235`, no rewiring). `LabeledTensor`
is introduced as a **new class** in `src/core/labeled-tensor.ts`
owning `EngineTensor` + `TensorEngine` + labels. The bridge between
AST `freeIndices` and wrapper `Labels` is built **only for evaluator
entry points that opt in** (Phase 4 demonstrates for one bridge).
Other evaluators continue to flow `ExprNode → validate → lowering →
engine` as in v0.6.1.

Shape (C) rejected: parallel string-keyed and identity-keyed systems
are exactly the redundancy §2.2 flags ("two strings that happen to be
equal"). Shape (B) rejected as out-of-scope for one release.

**Rationale.** v0.6.0 Decision #5 (`CurvatureCompositeNode<K,S>`
factory) set the precedent that bulk migrations are NOT free even when
LOC delta favors them. Bulk-migrating 42 bridges to `UniversalIndex`
would force `TensorSymbolNode.indices` to either change shape
(breaking v0.6.0 API) or carry parallel label systems on every node
(v0.5.0 ricci-slot-trap pattern). v0.7.0 keeps both worlds intact
and demonstrates the wrapper on the catalog-facing edge.

### Decision #2 — `UniversalIndex` ships with `axis`, `name`, `tags`, `limits?`, `notes?` — **NOT prime or arrow** in v0.7.0

The brief specifying Proposal 1 mentions "name, dimension, prime mark,
and arrow (per the ITensor design)." Proposals doc §2.2 sketch does
NOT include `prime` or `arrow` (only `id`, `axis`, `name`, `tags`,
`limits`, `notes`).

**UNVERIFIED**: Whether ITensor's Index actually carries an arrow
direction field (QN-sector dagger-relevant) and whether prime marks
are first-class on the Index or a separate `prime(index)` operation.
The proposals doc cites Section 3 and 8.2 but paraphrases through the
CHANGELOG-grounded investigation in §0/§1, not by direct re-reading.
Phase 0 Task 0.6 closes this either by direct paper read or by
locking the §2.2 sketch as canonical v0.7.0.

**v0.7.0 ships only the §2.2 fields.** **Deferred to v0.8.0+** with
explicit verification gate: `prime: number` (bra/ket distinguishing),
`arrow: 'in' | 'out'` (QN-aware direction). If a v0.7.0 acceptance
test *needs* prime or arrow, the release re-scopes — it does NOT
silently extend the type mid-cycle.

### Decision #3 — `LabeledTensor.contract(other)` matches by `UniversalIndexId` (UUID), not by `axis` or `name`

The contract algorithm:

1. `shared = labels(this) ∩ labels(other)` by full `UniversalIndexId`
   equality.
2. Each shared id becomes one `EinsumContraction` over the matching
   `(operand, axis)` coordinates.
3. The non-shared ids in both operands become the free axes of the
   result, in `this`-first, `other`-second order.
4. Call `engine.einsum(spec, this.tensor, other.tensor)`.
5. Return `new LabeledTensor(result, remainingLabels)`.

Strictly identity-based. Two `UniversalIndex` objects that share a
`name` and not an `id` do not contract and are not an outer product.
`contract` throws and the error names both ids. Indices whose names
differ and whose ids differ stay free axes. The `Axes` registry
(Decision #4) guarantees same-object identity at the consumer surface.

### Decision #4 — `Axes` is the canonical singleton registry, built at module load

`Axes.scale.quantum`, `Axes.scale.classical`, `Axes.force.electromagnetic`
etc. are stable references created exactly once per module load. The
implementation pattern uses `Object.freeze` at both the outer
namespace and the per-axis sub-objects. The exact count of regimes
per axis is **deferred to Phase 0 Task 0.1** (axis census against
`src/bridges/index.ts`) — the proposals doc §2.4 figures ("4 scales,
5 forces, 4+placeholder symmetries, 4 information measures") may be
stale relative to the v0.6 catalog as actually shipped.

Module-load semantics: `Axes` is computed exactly once per Node
process. Side-effect ordering: `src/core/axes-registry.ts` imports
only from `src/core/types.ts` and a new `src/core/universal-index.ts`
(the type + `makeIndex` factory). NO circular deps with `bridges/`.

### Decision #5 — `LabeledTensor` composes (does NOT extend); the §2.2 sketch needs translation for UPT shape

Proposals doc §2.2 sketches `constructor(readonly tensor: Tensor, readonly
labels: Labels)` where `Tensor` is MathTS's class. UPT's engine-level
handle is the opaque `EngineTensor` *interface*, not a class
(`src/numerical/tensor-engine.ts:22-24`) — inheritance isn't on the table.

Divergences from §2.2 (flagged in Phase 2 task descriptions so TDD
doesn't silently inherit them):

- `readonly tensor: Tensor` → `readonly tensor: EngineTensor`. UPT
  doesn't depend on `@danielsimonjr/mathts-tensor` at the wrapper
  level — the engine abstraction is the boundary.
- `Tensor.einsum(einsumStr, ...)` → `engine.einsum(spec, ...operands)`.
  UPT's einsum is **spec-based, not string-based**
  (`src/numerical/tensor-engine.ts:42-45`,
  `src/numerical/float64-engine.ts:492-582`).
- Add `engine` field to constructor — both
  `Float64ReferenceEngine` and `MathTSEngine` must work identically,
  so the engine handle is captured at construction.
- `LabeledTensor<any>` parameters → typed `LabeledTensor<R extends
  Record<string, UniversalIndex<AxisName>>>` with `MergedLabels<L, R>`
  result type. Decision #6 keeps generics precise.

### Decision #6 — `Labels` is `Record<string, UniversalIndex<AxisName>>` — structural string keys, no branded `EinsumLabel` type

The string key is engine-facing implementation detail; identity and
axis checks happen on the *value* (the `UniversalIndex`), not the
key. Branding the key would require callers to thread `makeLabel('i')`
instead of `'i'` and yields no incremental safety. The generic is
preserved through `contract()` so result label-record types are
precise.

### Decision #7 — `contract` rejects axis-mismatch contractions at runtime, not compile-time in v0.7.0

Cross-axis contraction (e.g., a `'scale'` index against a `'force'`
index) is a physics error. Proposals doc §2.3 claims this catches
"before the einsum string is built." Compile-time rejection in TS
would require encoding axis identity in the type-level shape of the
contraction — feasible with template literal types but expensive in
compile time and brittle in error messages.

**v0.7.0 ships runtime rejection.** `AxisMismatchError` thrown by
`contract` before calling `engine.einsum`; error names both indices,
both axes, both operand positions. Acceptance criterion §2.4
("wrong-axis contractions caught before the einsum string is built")
is satisfied by the runtime variant; v0.8.0+ may upgrade to
compile-time without breaking the runtime guarantee.

### Decision #8 — No AST-level integration in v0.7.0

The most tempting scope creep: plumbing `UniversalIndex` into the AST
(`TensorSymbolNode.indices[k].universalIndex?`) and teaching
`computeContraction` to consult it. **Rejected** — `TensorSymbolNode`
shape change ripples through 42 bridge modules; `computeContraction`'s
string-equality contract becomes mixed-mode (v0.5.0 ricci-slot-trap
pattern); and Phase 4's demonstration covers the wrapper pattern at
the evaluator surface (NOT the AST), preserving the proposals-doc-
claimed scope of "wrapper, not replacement." If v0.8.0+ proceeds with
shape (B), it gets its own release.

### Decision #9 — Engine-agnostic; both engines participate

The wrapper consumes the `TensorEngine` interface
(`src/numerical/tensor-engine.ts:67-116`) — `einsum`, `transpose`,
`reshape`. Works with `Float64ReferenceEngine` and `MathTSEngine`
identically. The existing engine-conformance suite is not modified;
a wrapper-level conformance subset is added that runs against either
engine via parameterization.

### Decision #10 — Public-surface additions are `@public`-tagged at declaration

Per v0.6.1 Decision #4. Additions: `Axes` (registry singleton),
`UniversalIndex<Axis>` (type), `UniversalIndexId` (branded type),
`AxisName` (union), `LabeledTensor` (class), `makeIndex` (factory),
the new error classes. `tests/api/public-surface.test.ts` snapshot
regenerated as part of Phase 4 commit. No symbols removed.

## Phase 1 — `UniversalIndex` type + `Axes` registry

### Theoretical motivation

`UniversalIndex` is the persistent-identity carrier that distinguishes
Proposal 1 from naive einsum string-labels. Per §2.3, the catch is
**identity-aware merging**: two AST trees referencing
`Axes.scale.quantum` get the *same object*, not two equal strings. The
registry singleton (Decision #4) guarantees this at module load.

### Components

- **`src/core/universal-index.ts`** — `UniversalIndexId` (branded
  type); `AxisName` union (`'scale' | 'force' | 'symmetry' |
  'information' | 'dimension' | 'topology'`);
  `UniversalIndex<Axis extends AxisName>` interface; `makeIndex<Axis>(axis,
  name, opts?)` factory generating `id` via `crypto.randomUUID()`.
- **`src/core/axes-registry.ts`** — `Axes` singleton
  `Object.freeze({ scale: Object.freeze({...}), force: ..., ... })`
  with per-namespace entries from Phase 0's census (Task 0.1).
- **`src/index.ts` re-exports** — Decision #10 list, added after
  `bridges/index.ts` exports, before the numerical-engine block.

### Tests

- `tests/core/universal-index.test.ts` — `makeIndex('scale', 'quantum')`
  returns `{axis: 'scale', name: 'quantum', id: <UUID>}`; two consecutive
  calls produce *different* `id`s; brand check via `// @ts-expect-error`
  (plain string cannot be assigned to `UniversalIndexId`).
- `tests/core/axes-registry.test.ts` — `Axes.scale.quantum` is the SAME
  reference across two import sites (singleton); `axis === 'scale'`;
  frozen-ness (reassignment throws in strict mode); every entry's
  `axis` equals its parent-namespace key.

### Pre-execution verification gate

## Phase 2 — `LabeledTensor` wrapper + `contract()`

### Theoretical motivation

`LabeledTensor` is the engine-facing wrapper. The single critical
operation is `contract(other)`. Per Decision #3, contract is strictly
identity-based — `UniversalIndexId` equality is the only matching
predicate. Per Decision #5, the wrapper composes `EngineTensor` +
`TensorEngine` + a labels record.

### Components

- **`src/core/labeled-tensor.ts`** (full implementation building on
  Phase 0's header):
  - Constructor `(tensor: EngineTensor, engine: TensorEngine, labels:
    Record<string, UniversalIndex<AxisName>>)`. Enforces
    `Object.keys(labels).length === tensor.shape.length`.
  - `contract(other)` per Decision #3: (1) find shared
    `UniversalIndexId` set; (2) for each shared id, build
    (operand, axis) coordinates from label-key position in canonical
    order (`canonicalLabelOrder(labels)` helper — Risk 2 mitigation,
    not raw `Object.entries`); (3) build `EinsumSpec`; (4) call
    `engine.einsum(spec, this.tensor, other.tensor)`; (5) build
    result labels with id-conflict guard (Phase 3).
  - `transpose(axisMap)` — rewires labels, calls `engine.transpose(t,
    perm)` with perm from axisMap.
  - `reshape(shape)` — calls `engine.reshape(t, shape)` with
    rank-preservation guard. Rank-changing reshape throws
    `RankPreservationError`; v0.7.0 allows only axis-by-axis size
    change (`[4, 4]` → `[2, 2, 4, 1]` rejected). v0.8.0+ may add
    explicit `mergeAxes` / `splitAxis`.

### Cross-check against the §2.2 sketch — divergences flagged

Per Decision #5. The implementation-plan task descriptions explicitly
list these divergences so TDD does not silently inherit the
MathTS-shaped sketch:

- `Tensor` → `EngineTensor`.
- `Tensor.einsum(einsumStr, ...)` → `engine.einsum(spec: EinsumSpec,
  ...operands)`.
- Add `engine` field to constructor.
- Typed generics (`L extends Record<string, UniversalIndex<AxisName>>`)
  instead of `<any>`.

### Tests

- `tests/core/labeled-tensor.test.ts` — **Construction**: label count
  matches rank or throws `LabeledTensorConstructionError`.
  **Identity contraction**: two tensors sharing `Axes.scale.quantum`
  produce a result with one fewer axis; label set is union minus
  shared id. **Non-identity contraction (negative)**: two tensors with
  `Axes.scale.quantum` vs `Axes.scale.classical` produce NO
  contractions (outer product). **Engine-agnostic conformance**: same
  fixture on both engines; outputs via `engine.toNested()` must match.
  **transpose passthrough**: re-ordered labels follow engine transpose.
  **reshape rank-preservation guard**: rank-changing reshape throws.

### Mid-cycle Adam+Eve vet (Phase 2 → 3)

The `contract()` algorithm is the highest-stakes commit. Adam re-derives
*independently* from `EinsumSpec` semantics
(`src/numerical/tensor-engine.ts:29-45`). Eve red-teams identity-conflict
cases: triple contraction (three operands sharing one id),
`Object.entries` order variance, contract chains > 2. Findings reconcile
into Phase 3.

## Phase 3 — Identity-aware merge + axis-mismatch + runtime guards

### Theoretical motivation

Phase 2 lands the happy path; Phase 3 lands the error surface. Cross-
classify proposals doc §2.3 against the v0.7.0 implementation:

| §2.3 claim | v0.7.0 catch level | Mechanism |
|---|---|---|
| Typos at construction (`Axes.scale.quantam`) | tsc compile-time | Typed object literal; non-existent keys are tsc errors (Phase 1). |
| Cross-axis errors (`force.weak` where `UniversalIndex<'scale'>` required) | tsc compile-time | `Axis extends AxisName` generic propagates (Phase 1). |
| Identity-aware merging | runtime + tsc (partial) | `contract` matches by `UniversalIndexId` (Phase 2). |
| Wrong-axis contractions in `LabeledTensor` ops | runtime | `AxisMismatchError` thrown by `contract` (Phase 3). |

### Components

- **`src/core/errors.ts` extensions** — `AxisMismatchError`,
  `LabeledTensorConstructionError`, `RankPreservationError`,
  `IdentityConflictError`. Placement aligned with existing error
  conventions (`src/numerical/errors.ts`, `src/dimensional/errors.ts`).

- **Runtime guards in `LabeledTensor.contract`**:
  - **Identity-conflict guard**: if `this.labels` and `other.labels`
    both have a remaining (non-contracted) label with the same id,
    throw `IdentityConflictError`. Same physical axis showing up
    free on both sides — physically meaningful but engine-level
    ambiguous.
  - **Axis-mismatch guard** (Decision #7): if `this.labels[k]` and
    `other.labels[m]` share an `id` but differ in `axis`, throw
    `AxisMismatchError`. Impossible if Phase 1's registry invariant
    holds; defensive against downstream consumers constructing
    off-registry indices via direct `makeIndex` calls.

### Tests

- `tests/core/labeled-tensor-errors.test.ts` — exhaustive coverage of
  the four guard types with edge-case inputs.

- `tests/core/labeled-tensor-conformance.test.ts` (engine-parameterized)
  expanded: all error cases run on both engines.

### Pre-execution verification gate

Per CLAUDE.md — read `src/numerical/errors.ts` and
`src/dimensional/errors.ts` before writing `src/core/errors.ts`, to
align with existing conventions (`NumericalBackendError`,
`DimensionMismatchError`, `IndexLabelCollisionError`,
`VarianceMismatchError`).

## Phase 4 — Single-bridge demonstration + docs + release prep

### Theoretical motivation

Proposals doc §2.4's "All 42 v0.6 bridges re-register through Index
objects" is moved out of v0.7.0 (non-goal). What v0.7.0 demonstrates
is the *pattern* on a single representative bridge — enough to
validate the wrapper-on-the-catalog-edge claim and to provide a
tutorial for downstream maintainers and physicist contributors.

### Components

- **Bridge choice — BE-52 (Mercury perihelion) OR BE-21 (Wheeler-
  DeWitt)**. BE-52 has a richer numerical surface; BE-21 is closer to
  the regime-bridging spirit. Phase 0 Task 0.1's axis census informs
  the choice — the implementation-plan task description pins exactly
  one.

  **Constraint**: the demo MUST NOT modify the chosen bridge's
  existing AST evaluation path. The `LabeledTensor` wrapping is added
  as an *alternative* entry point (e.g.,
  `evaluateBE52WithLabeledOutput(...)` returning a `LabeledTensor`
  whose axes are tagged via `Axes.scale.cosmological` etc.), and the

## Risks

1. **Phase 0 invalidates adapter-on-top (Decision #1)**. Probability low
   (AST and engine paths well-separated per ARCHITECTURE.md), but if it
   fires, release re-scopes to v0.8.0 with breaking-change carry-forward.
   *Mitigation*: Task 0.2 produces a written verification artifact the
   design vet signs off on.

2. **`Object.entries` order non-determinism in `contract()` mapping**. JS
   guarantees string-key insertion order, but `Record<string, ...>` doesn't
   make that explicit at type level. *Mitigation*: Phase 2 commits a
   `canonicalLabelOrder(labels): string[]` helper; the algorithm threads
   through that, not raw `Object.entries`.

3. **`prime` / `arrow` ITensor parity demanded mid-cycle**. If a reviewer
   argues the wrapper is "incomplete" without prime marks (bra/ket
   distinction in QFT-side bridges), field as v0.8.0 brainstorm seed —
   NOT a v0.7.0 scope addition. *Mitigation*: Phase 0 Reconciliation
   memo names the v0.7.0/v0.8.0 split explicitly.

4. **Engine-agnostic claim fails for `MathTSEngine`**. The wrapper assumes
   `engine.einsum(spec, ...)` accepts the same `EinsumSpec` on both engines.
   *Cross-check status*: this design has NOT directly read
   `src/numerical/mathts-engine.ts` (large, behind optional dep).
   *Mitigation*: Phase 2 engine-conformance suite runs `LabeledTensor.contract`
   tests against both engines; if MathTSEngine fails, demo bridge falls back
   to `Float64ReferenceEngine` and the gap is a v0.8.0 follow-up.

5. **Phase 4 demo bridge wiring leaks into the AST**. Decision #1's
   "`TensorSymbolNode` and `computeContraction` UNCHANGED" invariant is
   the hardest to keep — it's tempting to thread a `UniversalIndex`
   reference through `TensorSymbolNode.indices[k]` "just for the demo"
   (v0.5.0 ricci-slot-trap pattern). *Mitigation*: Phase 4 explicitly
   forbids any `src/dimensional/*` or `src/bridges/equations/*` edits
   beyond the demo bridge evaluator entry-point body. Pre-publish vet
   greps for unintended edits.

6. **Public-surface explosion**. Decision #10 adds ~7 new exports.
   *Mitigation*: each carries a JSDoc paragraph (Phase 4); snapshot
   regen is a single deliberate commit, not drift.

7. **`crypto.randomUUID` availability**. Per Node ≥18, available
   globally; not directly verified in tsconfig/test-runner for this
   design. *Mitigation*: Phase 1 Task 0 includes a one-line preflight;
   fall back to `node:crypto` import if absent.
