# UPT v0.4.5 — DRY + Dead-Code + Benchmark Scaffold — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a pure refactor + benchmark-infrastructure release. No new features, no bridge work (that is v0.5.0), no breaking changes. Two phases: Phase 1 removes dead exports and extracts the bridge-test boilerplate into a shared helper (identified by the v0.4.5 pre-flight refactor analysis); Phase 2 installs the `bench/` directory with Vitest's native bench API and records baseline timings for the three performance-critical paths in the codebase.

**Architecture:** All Phase 1 changes are surgical deletions or mechanical rewrites — no design decisions required. The one deliberate call already made by the owner: `Float64Tensor` is `@internal`, and its `export` keyword will be removed; the class has never appeared in `src/index.ts` and is not in the public surface, so this is non-breaking. Phase 2 reuses the existing Vitest 4.1.4 devDependency (`vitest bench`) — no new devDependency is needed. Bench files live under `bench/*.bench.ts` and are excluded from the normal test pass by the existing `vitest.config.ts` `include` pattern.

**Spec:** `docs/architecture/archive/v0.4.5-refactor-targets.md` (generated 2026-05-16 by direct code inspection). All 10 tasks derive from that analysis — every verdict was independently verified against source and test files; static-analyzer output from the earlier unused-analysis pass was the starting checklist only.

### Task 5a [U]: Bridge test helpers — pilot (3-5 files, establish pattern)

Extract the repeated 3-part boilerplate (catalog lookup + dimensional validation + round-trip pin) shared by all ~39 bridge encoding test files into a shared `tests/bridges/_helpers.ts`. Task 5a creates the helper and migrates 3-5 pilot files to establish the pattern and validate the helper API before the bulk sweep. **Helper API is frozen after 5a commits.**

**Design constraint (F5):** `expectBridgeInIndex` and `expectDimRoundTrip` must NOT be called at describe/module scope. Calling `expect()` outside an `it()` block causes Vitest to report an uncaught error and reduces per-bridge test count. Each migrated file KEEPS its own `it()` blocks; the helpers consolidate repetitive boilerplate INSIDE those `it()` blocks. The `expectBridgeInIndex` helper is called inside an `it('exists in the index and has correct status')` block; `expectDimRoundTrip` is called inside an `it('dimensional_signature round-trips')` block. The helpers do not replace `it()` — they replace the body of `it()`.

**LOC impact (revised from F5):** ~150-200 net LOC reduction (retaining `it()` structure eliminates the body duplication but not the `it()` wrapper lines themselves).

The refactor-targets doc identifies two helpers:
- `expectBridgeInIndex(id, status?)` — catalog-lookup + status pin called INSIDE an `it()` block; returns the entry for further assertions.
- `expectDimRoundTrip(rhs: ExprNode, sig: string)` — validate + format round-trip called INSIDE an `it()` block.

**Files:**

- Modify: 3-5 pilot `tests/bridges/be-NN-encoding.test.ts` files (Parts I)

The fix-test files (`be-11-fix.test.ts`, `be-47-fix.test.ts`, `be-48-fix.test.ts`) have non-standard structures — inspect each before deciding whether to migrate.
