## 1. Goal

Land the **GR foundations** that v0.4.0 deferred and the bridge-validation precision that v0.4.6 documented but did not enforce. Concretely: (a) ship a symplectic geodesic integrator (Gauss-Legendre 4th-order, canonical (x,p) state) + bisection perihelion finder so the two `it.skip` cross-validation tests from v0.4.0 (BE-52 Mercury Δφ, BE-37 full Shapiro via geodesic) can be **activated** rather than deferred again; (b) ship the curvature layer (`RiemannTensorNode` AST + `ricci()` / `einstein()` / `bianchiResidual()` helpers) so v0.6.0+ Friedmann-flavored cosmology bridges have the infrastructure they need; (c) close the structural-parity gaps surfaced by the v0.5.0 pre-flight bridge-coverage audit (BE-51 + BE-52 sibling structural tests, plus ~5 catalog-only bridges getting tighter physics anchors).

Pure-additive — no breaking changes. Pattern-mirrors v0.4.0 (CovariantDerivativeNode + christoffel helper) one level up.

## 2. Architecture summary

### Four locked architectural decisions

| # | Decision | Chosen | Rationale |
|---|---|---|---|
| 1 | **Scope** | **Maximal v0.5.0**: bridge validation + symplectic + curvature, all three blocks in the same release. | The three blocks share testing infrastructure (Schwarzschild fixture, geodesic integrator) and share the `it.skip` debt-clearance theme — splitting them produces three half-releases with overlapping test surfaces. |
| 2 | **Symplectic algorithm** | **Gauss-Legendre 4th-order** (2-stage implicit Runge-Kutta, symmetric Butcher tableau). | Mercury Δφ_GR ≈ 5.02·10⁻⁷ rad/orbit requires a true symplectic integrator over multi-orbit integration. Ruth-4 (Yoshida) is symplectic **only** for separable Hamiltonians `H = T(p) + V(q)`; the geodesic Hamiltonian `H = ½ g^μν(x) p_μ p_ν` is NOT separable because `g` depends on `x`. Gauss-Legendre 4-stage is symplectic for **any** Hamiltonian via its symmetric Butcher tableau — it preserves the symplectic 2-form exactly (modulo roundoff) for non-separable systems. State variables are canonical `(x, p)` not `(x, v)` — kicking `v` instead of `p` breaks symplecticity regardless of integrator; see §5.3. Butcher tableau and Legendre coefficients pinned (§5.3). |
| 3 | **Curvature API** | **Mixed pattern**: `RiemannTensorNode` is a first-class `ExprNode` kind (operator); `ricci(R)`, `einstein(R, g)`, `bianchiResidual(R)` are **helpers** that build composite trees from existing v0.4.0 primitives (CovariantDerivativeNode + raise/lower + tensor-product + contract). | Mirrors v0.4.0's locked precedent (`CovariantDerivativeNode` = node; `christoffel()` = helper). Riemann is the **operator** users write; Ricci/Einstein are *contractions* of Riemann — formulaic, not primitive. Bianchi is a *residual identity*, not an operator. |
| 4 | **Sequencing** | **Bottom-up**: Phase 1 Foundations → Phase 2 Activations → Phase 3 Validation → Phase 4 Release. | Phase 2 activations literally cannot fire without Phase 1 (symplectic + bisection) shipped; Phase 3 bridge-validation needs the activated infrastructure to anchor against. Top-down would invert the dependency graph and force late refactors. |

## 3. Detailed design per phase

### Phase 1 — Foundations (~12–15 tasks)

#### Task 1a — Gauss-Legendre 4th-order symplectic integrator

**Files**:
- Create: `src/numerical/gl4-integrator.ts` (~180–220 LoC; replaces the Ruth-4 design).
- Test: `tests/numerical/gl4-integrator.test.ts` (new).
- Modify: `src/numerical/index.ts` (export `integrateGeodesicGL4`).

**State variable change (S1 / owner decision)**: state is now **canonical `(x, p)`** where `p_μ = g_μν(x) v^ν` (covariant momentum), NOT `(x, v)`. Kicking `v` (not `p`) destroys the symplectic form regardless of integrator. Conversion at integrator construction: `p_μ = g_μν(x₀) v₀^ν`. Conversion at output (if caller wants 4-velocity): `v^ν = g^μν(x) p_μ`.

**Key signatures**:
```typescript
export interface GL4State {
  /** Coordinate 4-vector x^μ. */
  readonly x: readonly number[];
  /** Covariant momentum p_μ = g_μν v^ν. */
  readonly p: readonly number[];
}
export interface GL4Snapshot {
  /** Proper time / affine parameter. */
  readonly tau: number;
  readonly x: readonly number[];
  readonly p: readonly number[];
  /** 4-velocity v^ν = g^μν p_μ (computed at snapshot, optional convenience). */
  readonly v?: readonly number[];
}
export interface GL4Options {
  /** Step count (uniform stepping; GL4 requires Newton iteration per step). */
  readonly steps: number;
  /** Final proper time (or affine parameter for null geodesics). */
  readonly tauMax: number;
  /** Metric inverse g^μν(x): used to derive Hamilton equations. */
  readonly gInverseFn: (x: readonly number[]) => readonly number[][];
  /** Partial derivatives ∂_λ g^μν(x): needed for Hamilton's equations of motion. */
  readonly dgInverseFn: (x: readonly number[]) => readonly number[][][];
  /** Newton iteration tolerance (default 1e-12). */
  readonly newtonTol?: number;
  /** Max Newton iterations per stage (default 50). */
  readonly newtonMaxIter?: number;
  /** Domain restriction (e.g., r ≥ 3·r_s for Schwarzschild). */
  readonly domainMinRadius?: number;
}
export function integrateGeodesicGL4(
  initialState: GL4State,
  options: GL4Options,
): ReadonlyArray<GL4Snapshot>;
```

**Algorithm** (2-stage Gauss-Legendre implicit Runge-Kutta; Hairer/Lubich/Wanner §II.1):

Gauss-Legendre 4th-order is a 2-stage collocation method with Butcher tableau:
```
Butcher tableau (GL4, 2 stages):
  c₁ = ½ − √3/6    a₁₁ = ¼           a₁₂ = ¼ − √3/6
  c₂ = ½ + √3/6    a₂₁ = ¼ + √3/6    a₂₂ = ¼
                    b₁ = ½             b₂ = ½

Quadrature nodes:  c₁ ≈ 0.2113248654, c₂ ≈ 0.7886751346
Stage weights:     b₁ = b₂ = 0.5
```

Hamiltonian equations of motion (from `H = ½ g^μν(x) p_μ p_ν`):
```
dx^μ/dτ = ∂H/∂p_μ = g^μν(x) p_ν
dp_μ/dτ = −∂H/∂x^μ = −½ (∂_μ g^νρ)(x) p_ν p_ρ
```

For each step of size h, solve the implicit system for stage values `(X₁, P₁), (X₂, P₂)`:
```
X_i = x_n + h · Σ_j a_{ij} · g^{·ν}(X_j) P_{j,ν}      (i = 1, 2)
P_{i,μ} = p_n − h · Σ_j a_{ij} · ½ (∂_μ g^νρ)(X_j) P_{j,ν} P_{j,ρ}
```
Solved via **fixed-point / simplified Newton iteration** (explicit dependence on previous Newton iterate — data flows from `(X_j, P_j)` at iterate `k` to update `(X_i, P_i)` at iterate `k+1`; no simultaneous cross-stage coupling in the linearised system because the Jacobian of the simplified Newton step decouples the two stages under the standard GL diagonal-block approximation). Iterate until `max‖δX, δP‖ < newtonTol` or `newtonMaxIter` reached.

Update:
```
x_{n+1} = x_n + h · (b₁ · g^{·ν}(X₁) P_{1,ν} + b₂ · g^{·ν}(X₂) P_{2,ν})
p_{n+1} = p_n − h · (b₁ · ½ (∂_μ g^νρ)(X₁) P_{1,ν} P_{1,ρ} + b₂ · ½ (∂_μ g^νρ)(X₂) P_{2,ν} P_{2,ρ})
```

**Symplecticity** (proof sketch): GL4 is a Gauss collocation method; all Gauss methods satisfy the symplecticity condition `b_i a_{ij} + b_j a_{ji} = b_i b_j` for all `i,j` (Sanz-Serna 1988). This holds for ANY smooth Hamiltonian including `H = ½ g^μν(x) p_μ p_ν`; no separability assumption.

**Test approach**:
1. Schwarzschild radial-infall cycloid fixture — GL4 must match cycloid to **≤1e-13 relative** at 5000 steps (same target as the previous Ruth-4 design; GL4 has the same 4th-order accuracy per step).
2. Energy-conservation test: bound Mercury-like orbit, 100 orbits, Hamiltonian drift `|H(t) − H(0)| / |H(0)| ≤ 1e-10` over the full run. (True symplectic for non-separable H — this tolerance IS achievable; see I1 reconciliation in §11.)
3. Symplectic-form preservation: two initial `(x, p)` states displaced by `δ`; the phase-space volume `δx ∧ δp` preserved to ≤1e-12 after one orbit. (Cheap sanity check.)
4. Newton convergence smoke test: at each step, Newton iteration must converge in ≤20 iterations for the Schwarzschild Mercury-scale orbit at the chosen step size. Fails the test if `newtonMaxIter` is hit in >0.1% of steps.

**Dependencies**: none — GL4 is self-contained. `GL4State`/`GL4Snapshot` are new types (v0.4.0 `GeodesicState`/`GeodesicSnapshot` are retained for backward compatibility with the existing RK4 integrator path).

**Honest framing**: GL4 requires **Newton iteration per step** (implicit RK). This is more expensive than Ruth-4's explicit drift-kick per step. Cost per step: 2 stages × ≤50 Newton iterations × (g^μν eval + ∂g^μν eval). For Mercury 2-orbit at 50k steps this is acceptable on CI but slower than the Ruth-4 alternative would have been. The win is **correct symplecticity for non-separable H** — Ruth-4 would have a secular non-symplectic error because the geodesic Hamiltonian mixes x and p inside g^μν(x).

#### Task 1b — Bisection perihelion finder

**Files**:
- Create: `src/numerical/perihelion-finder.ts` (~80–120 LoC).
- Test: `tests/numerical/perihelion-finder.test.ts` (new).
- Modify: `src/numerical/index.ts` (export `findPerihelion`).

**Key signatures**:
```typescript
export interface PerihelionOptions {
  /** Trajectory snapshots from integrateGeodesicGL4 (must include canonical p). */
  readonly snapshots: ReadonlyArray<GL4Snapshot>;
  /** Tolerance for bisection (proper-time precision target). */
  readonly tauTolerance: number;
  /** Metric inverse for extracting dr/dτ from p (g^μν at snapshot x). */
  readonly gInverseFn: (x: readonly number[]) => readonly number[][];
}
export interface PerihelionResult {
  /** Proper time of perihelion. */
  readonly tau: number;
  /** Position 4-vector at perihelion. */
  readonly x: readonly number[];
  /** Azimuthal angle φ at perihelion (extracted from x[3] in Schwarzschild coords). */
  readonly phi: number;
}
export function findPerihelion(opts: PerihelionOptions): PerihelionResult;
```

**Algorithm** (I6 bisection-cost fix: polynomial interpolation, not full re-integration):
1. Walk snapshots; find consecutive pair `(s_i, s_{i+1})` where `dr/dτ` changes sign from `−` to `+`. Radial velocity is extracted as `dr/dτ = g^{rν}(x) p_ν` (using canonical p — see S1 state-variable fix).
2. **Bracket-width check (M3)**: if `|τ_{i+1} − τ_i| < 2h` (narrower than one integrator step), the snapshot grid is too coarse — emit a warning and refine the enclosing step by sub-stepping GL4 at `h/10` for that step only, caching the sub-step snapshots. Do NOT proceed to bisection on sub-step-width brackets without this refinement.
3. **Bisect via polynomial interpolant**: fit a cubic Hermite polynomial through `(τ_i, dr/dτ_i)` and `(τ_{i+1}, dr/dτ_{i+1})` using `dr/dτ` values already in the snapshot cache. Evaluate the polynomial root — this gives a `τ_mid` estimate in O(1) without re-integrating. Cache sub-interval snapshots from step 2 for repeated evaluations.
4. If the polynomial root estimate has residual `|P(τ_mid)| > tauTolerance`, refine with one bisection step on the cached sub-snapshots (no full GL4 re-integration call per bisection step).
5. Terminate when `|τ_b − τ_a| < tauTolerance` (default suggestion: `1e-10 · T_orbit`).
6. Return final state's `τ, x, phi`.

**Test approach**:
1. Synthetic test: analytic cycloid (which has perihelion at `η = π`), inject `r(τ)` from the closed form, bisect → must find perihelion `τ` to ≤1e-12 relative.
2. Round-trip GL4: Mercury-scale ellipse integrated for one orbit via `integrateGeodesicGL4` on canonical (x, p) → bisection via polynomial interpolant finds perihelion → `φ_perihelion(orbit 2) − φ_perihelion(orbit 1)` must match `6πGM/(a(1−e²)c²)` to ±5×10⁻⁴ relative (consistent with 2a tolerance; see I4 reconciliation).

**Dependencies**: 1a (uses GL4 snapshots as input; sub-step refinement in step 2 re-uses `integrateGeodesicGL4`).

**Honest framing**: bisection precision floor is bounded by GL4's per-step error (~1e-13 per step). The 1e-10 × T_orbit target is conservative. Polynomial interpolation (step 3) avoids O(N log ε) full-integrations per bracket — the previous design's `refine` callback pattern would cost minutes per CI run over many bisection brackets. This does NOT block 2a (Δφ tolerance is ±5×10⁻⁴ relative, far above the bisection floor).

#### Task 1c — `RiemannTensorNode` (AST + validator + lowering)

**Files**:
- Modify: `src/dimensional/connection-validators.ts` — add `RiemannTensorNode` interface + `case 'riemann-tensor'` to `infer()`.
- Modify: `src/numerical/lowering.ts` — add `case 'riemann-tensor'` lowering.

**Key shapes**:
```typescript
// src/dimensional/connection-validators.ts
export interface RiemannTensorNode {
  readonly kind: 'riemann-tensor';
  readonly upperIndex: UpperIndex;            // ρ
  readonly lowerIndices: readonly [
    CovariantIndex,                            // σ
    CovariantIndex,                            // μ
    CovariantIndex,                            // ν
  ];
  readonly gLower: MetricTensorNode;
  readonly gInverse: MetricTensorNode;
  readonly xCoord: TensorSymbolNode;
}
```

**Index convention (locked, §5.1)**: 1 upper + 3 lower → `R^ρ_σμν` per Carroll Ch. 3. Definition (S3 corrected — Γ indices from Carroll §3.4):
```
R^ρ_σμν = ∂_μ Γ^ρ_σν − ∂_ν Γ^ρ_σμ + Γ^ρ_λμ Γ^λ_σν − Γ^ρ_λν Γ^λ_σμ
```
Note the index placement: in each Γ term, `σ` occupies the **second** lower slot (not the third). The `μ, ν` indices are the derivative/antisymmetry pair on the outer slots. This differs from the previous draft which had `σ` and `ν` swapped in the Γ factors.

**Validator output**: `freeIndices = {ρ: upper, σ: lower, μ: lower, ν: lower}`; `dim: { L: -2, M: 0, T: 0, I: 0, Theta: 0, N: 0, J: 0 }` (curvature has units 1/L² in SI — Riemann appears in tidal-force equations as `R^μ_νρσ u^ρ u^σ` contracted with velocity²/L → acceleration, consistent with SI; see I3 reconciliation in §11); `gLower`/`gInverse`/`xCoord` validated *without* propagating their free indices upward (same rule as `covariant-derivative` per v0.4.0 §7 H1 fix).

**Lowering**: `riemann-tensor` → emits a composite expression tree built from `christoffel()` outputs and `pderiv` of Christoffel, then computes numerically. The lowering pass is **NOT** a recursive AST rewrite at validation time (which would explode tree size — see §7 Risk Register); instead, lowering walks the `riemann-tensor` node directly, evaluating `Γ^ρ_νσ(x)` and `∂_μ Γ^ρ_νσ(x)` numerically at the supplied coordinate point using `derivativeStrategy`-honoring paths. Result: a 4×4×4×4 `EngineTensor`.

**Test approach**:
1. Validator: free-indices = `{ρ: upper, σ: lower, μ: lower, ν: lower}`; gLower/gInverse indices consumed internally; dim `{ L: -2 }`.
2. Numerical: Schwarzschild fixture → `R^ρ_σμν` components match Carroll Ch. 5 exercise values (e.g., `R^t_rtr = 2GM/r³` in SI units with c=1 geometric convention, `R^θ_φθφ = r_s/r · sin²θ`) to ≤1e-9 relative.
3. Antisymmetry: `R^ρ_σμν = −R^ρ_σνμ` to machine precision (structural check on lowered tensor).
4. **Pinning vitest (M7)**: one-line pinned closed-form assertion: `R^t_rtr(r=6M, M=M☉) === 2GM☉/(6M☉)³` to ≤1e-10 relative. Cross-checks the corrected Riemann formula (S3) at a concrete coordinate — catches index-permutation regressions.

**Dependencies**: none (uses v0.4.0 Christoffel infrastructure unchanged).

**Honest framing**: this is a 4-index tensor with 256 entries (4⁴). Lowering performance is bounded by 256 × (Christoffel-eval + Γ-derivative-eval) operations per point. Adequate for fixture-based testing; **not yet** optimized for grid-field curvature (which is what v0.6.0+ Friedmann/Raychaudhuri evaluation would need).

#### Task 1d — `ricci()` helper

**Files**:
- Modify: `src/dimensional/connection.ts` (add `ricci()` next to `christoffel()`) — OR create `src/dimensional/curvature.ts` for the three curvature helpers grouped together. **Decision**: new file `src/dimensional/curvature.ts` (separation of layers — connection vs curvature).
- Test: `tests/dimensional/ricci.test.ts`.

**Key signature** (M2: simplified — no explicit contraction-label parameters):
```typescript
export function ricci(R: RiemannTensorNode): ExprNode;
```

Builds the trace `R_μν = R^λ_μλν` (Carroll convention: contract upper `λ` against the **first lower** slot — the `μ` position — not the second lower slot). This is the corrected Ricci contraction (S2 fix). Internally uses the existing v0.2.0 `contract()` machinery. Symbolic, returns an `ExprNode`; numerical lowering happens via the existing pipeline.

**S2 correction note**: the previous draft wrote `R_σν = R^ρ_σρν` — this contracts upper `ρ` against the **second** lower slot (the `σ↔ρ` pair). Carroll's convention is `R_μν = R^λ_μλν` — contract upper `λ` against the **first** lower slot (the `μ` position). The difference is a permutation of `σ` and `μ` in the contracted pair; using the wrong slot produces the wrong Ricci tensor for non-symmetric Riemann components.

**Test approach**:
1. Output free-indices: `{μ: lower, ν: lower}`, dim `{ L: -2 }`.
2. Schwarzschild vacuum: `R_μν = 0` to ≤1e-12 (Ricci-flat is the *defining* property of vacuum solutions — this is **the** key curvature test).
3. de Sitter (constant-curvature) fixture: `R_μν = (Λ/3)·g_μν` for the de Sitter solution → trace `g^μν R_μν = R = 4Λ` (this re-uses BE-13's machinery, see §3 Phase 3).

**Dependencies**: 1c (RiemannTensorNode).

**Honest framing**: helper, not a node. The output AST is *bigger* than the input (it expands Riemann into a contracted tree). v0.6.0+ may add an `isRicciFlatVacuum` validator-level optimization that short-circuits the lowering for known vacuum metrics; v0.5.0 lowers everything generically.

#### Task 1e — `einstein()` helper

**Files**:
- Modify: `src/dimensional/curvature.ts` (add `einstein()` next to `ricci()`).

**Key signature**:
```typescript
export function einstein(
  R: RiemannTensorNode,
  g: MetricTensorNode,
  gInverse: MetricTensorNode,
): ExprNode;
```

Builds `G_μν = R_μν − ½ g_μν R` where `R = g^σν R_σν` (Ricci scalar). Uses `ricci()` internally + a fresh metric-trace contraction + scalar-multiply + tensor-subtract (all existing v0.2.0 ops). Output free-indices: `{μ: lower, ν: lower}`.

**Test approach**:
1. Schwarzschild vacuum: `G_μν = 0` to ≤1e-11 (since both `R_μν = 0` AND `R = 0`; same numerical fixture as 1d).
2. de Sitter: `G_μν + Λ g_μν = 0` to ≤1e-11 (matches BE-13's `G_μν = κ T_μν` with `T_μν = −(Λ/κ) g_μν` for cosmological-constant matter). This connects v0.5.0's curvature layer to v0.6.0+'s Einstein-field-equation work without committing to it.
3. Trace: `g^μν G_μν = −R` to machine precision (standard identity).

**Dependencies**: 1c (RiemannTensorNode), 1d (ricci).

**Honest framing**: `einstein()` returns `G_μν`. **Not** `G_μν − κ T_μν = 0` (no matter sources). Vacuum-Einstein-field-equation testing (G_μν = 0 for Schwarzschild) IS in scope; matter-coupled `G_μν = κ T_μν` is **v0.6.0+ work** (see §4 Honest Framing).

#### Task 1f — `bianchiResidual()` helper

**Files**:
- Modify: `src/dimensional/curvature.ts` (add `bianchiResidual()`).
- Test: `tests/dimensional/bianchi-residual.test.ts`.

**Key signature** (M4: return full tensor residual so callers can reduce as needed):
```typescript
export function bianchiResidual(
  R: RiemannTensorNode,
): {
  /** Symbolic residual tree — an ExprNode whose value is zero when the identity holds. */
  residual: ExprNode;
  /** Numerical full 5-index residual tensor R_λμνρσ_residual (callers reduce as needed). */
  evaluate: (engine: TensorEngine, inputs: NumericalInputs) => Promise<EngineTensor>;
  /** Convenience: max |residual_λμνρσ| across all free-index assignments. */
  evaluateMax: (engine: TensorEngine, inputs: NumericalInputs) => Promise<number>;
};
```

Returns the **cyclic-symmetry second Bianchi identity** form (all-lower `R_μνρσ` convention):
```
∇_λ R_μνρσ + ∇_μ R_νλρσ + ∇_ν R_λμρσ = 0   (identically, in any geometry)
```
(See §5.2 for choice rationale.)

**I7 — lowering step**: `RiemannTensorNode` is mixed (1 upper + 3 lower: `R^ρ_σμν`). The all-lower `R_μνρσ` required by the Bianchi identity is obtained by first lowering the upper `ρ` index via the metric: `R_λμνρ = g_λρ R^ρ_μνσ` using v0.3.0's `lower()` helper. This lowering step is applied inside `bianchiResidual` before constructing the `∇ + cyclic sum` expression tree. Callers pass `R: RiemannTensorNode` and do not need to pre-lower.

`residual` is the symbolic LHS as an `ExprNode`; `evaluate` returns the full 5-index residual tensor; `evaluateMax` is a convenience reduction over it.

**Test approach**:
1. Schwarzschild: `evaluateMax(...)` ≤ 1e-9 (identity holds; bounded by Christoffel-derivative numerical error). Honest framing: this is a sanity test that our curvature lowering is *self-consistent*, not a new physics claim.
2. de Sitter: same — residual ≤ 1e-9.
3. Synthetic broken-Christoffel injection: deliberately corrupt one Christoffel component → residual jumps to O(1). Confirms the test is not vacuously passing.

**Dependencies**: 1c (RiemannTensorNode), v0.4.0 CovariantDerivativeNode (for `∇_λ R`).

**Honest framing**: this is a **consistency check**, not new physics. Bianchi is a mathematical identity that *any* connection satisfies in 4d; we test it to confirm our implementations of Riemann + covariant-derivative are mutually consistent.

## 4. Honest framing

What v0.5.0 IS:
- The GR foundations release: symplectic integrator, bisection perihelion finder, curvature layer (Riemann + Ricci + Einstein + Bianchi).
- Activation of two v0.4.0 `it.skip` debts (BE-52 Mercury, BE-37 full Shapiro).
- Tightening of bridge-validation precision per the pre-flight audit.

What v0.5.0 is **NOT**:
- **Not a performance release.** Gauss-Legendre 4th-order is more expensive per step than RK4: 2 stages × ~20 Newton iterations each, versus 4 explicit stages for RK4. The win is *correct symplectic-form preservation for the non-separable geodesic Hamiltonian*, not speed. Mercury perihelion at 50k GL4 steps is slower than 50k RK4 steps; we pay that cost knowingly. Ruth-4 would have been cheaper but is NOT symplectic for the geodesic Hamiltonian (g^μν(x) mixes x and p — the Hamiltonian is non-separable).
- **Not a tensor-algebra refactor.** The existing v0.4.0 lowering pipeline is reused unchanged. RiemannTensorNode lowering walks the node directly (calling Christoffel + Γ-derivative at points) rather than AST-rewriting Riemann into thousands of pderiv nodes. Tree size stays bounded.
- **Not yet Einstein-field-equation work.** `einstein()` returns `G_μν`. Vacuum testing (`G_μν = 0` for Schwarzschild) IS in scope. **Matter-coupled** `G_μν = κ T_μν` requires a stress-energy AST kind (`stress-energy-tensor`?), matter Lagrangian primitives, and is **v0.6.0+ work**.
- **Not yet Friedmann/Raychaudhuri/cosmology bridges.** Those depend on `einstein()` + matter sources + cosmological metrics. v0.5.0 ships the LHS (`G_μν`); v0.6.0+ ships the RHS (`κ T_μν`) and writes the bridges.
- **Not yet threejs visualization.** The GL4 `GL4Snapshot` shape mirrors the v0.4.0 RK4 `GeodesicSnapshot` (τ + coordinates); future viz can consume both shapes without API churn. The canonical-p state is internal to the integrator; output snapshots expose x and optional v.
- **Not yet higher-order AD.** Riemann involves `∂Γ`; we evaluate `∂Γ` via `pderiv` finite-difference, NOT via forward-over-forward AD composition (which v0.4.0's interface supports structurally per §14.4). v0.5.0 chose finite-difference because Christoffel finite-differencing IS already the v0.4.0 'computed' strategy path; we reuse it without introducing nested-AD complexity. AD-on-curvature is a v0.6.0+ optimization.

## 5. Math conventions

### 5.1 Riemann index convention (Carroll Ch. 3)

`R^ρ_σμν` — 1 upper + 3 lower. Definition (S3 corrected; Carroll §3.4):
```
R^ρ_σμν = ∂_μ Γ^ρ_σν − ∂_ν Γ^ρ_σμ + Γ^ρ_λμ Γ^λ_σν − Γ^ρ_λν Γ^λ_σμ
```
Index-placement key: `σ` is the **second** lower slot in every Γ factor; `μ, ν` appear as the derivative/antisymmetry pair on the outer Γ slots (`σν`, `σμ`). The previous draft had `σ` and `ν` swapped in the Γ terms, which is incorrect per Carroll.

**Antisymmetries** (validator-asserted):
- `R^ρ_σμν = −R^ρ_σνμ` (last two lower indices)
- After lowering `ρ`: `R_ρσμν = −R_σρμν` (first two indices); `R_ρσμν = R_μνρσ` (pair-swap).

**Contractions** (used by `ricci`/`einstein`):
- Ricci: `R_μν = R^λ_μλν` (S2 corrected: trace on upper `λ` ↔ **first lower** slot, the `μ` position). Carroll convention; previous draft incorrectly used the second lower slot.
- Ricci scalar: `R = g^μν R_μν`.

### 5.2 Bianchi identity form (cyclic vs alternative)

**Chosen form** (cyclic on first three lower indices of `∇R`, all-lower convention):
```
∇_λ R_μνρσ + ∇_μ R_νλρσ + ∇_ν R_λμρσ = 0
```
This is the standard second Bianchi (per Carroll Eq 3.95). Alternative forms (e.g., `∇_λ R^ρ_σμν + ...` with one upper index, or the *first* Bianchi `R^ρ_[σμν] = 0` on the index ordering) are mathematically equivalent but bury the symmetry. Cyclic-all-lower is the textbook "look at me, I'm cyclic" form most readers recognize. For Schwarzschild we expect residual ≤ 1e-9 (bounded by Christoffel-pderiv numerical noise).

### 5.3 Gauss-Legendre 4th-order coefficients (2-stage GL; Hairer/Lubich/Wanner §II.1)

The 2-stage Gauss-Legendre method has quadrature nodes at the roots of the shifted Legendre polynomial `P₂(2t−1) = 0`:
```
c₁ = ½ − √3/6   ≈  0.2113248654051871
c₂ = ½ + √3/6   ≈  0.7886751345948129
```

Butcher tableau `a_{ij}`:
```
a₁₁ = ¼               ≈  0.25
a₁₂ = ¼ − √3/6        ≈  0.0669872981077807
a₂₁ = ¼ + √3/6        ≈  0.4330127018922193
a₂₂ = ¼               ≈  0.25

b₁ = b₂ = ½           (quadrature weights)
```

**Symplecticity condition** (Sanz-Serna 1988): verify `b_i a_{ij} + b_j a_{ji} = b_i b_j` for all `i, j`:
- `i=j=1`: `b₁ a₁₁ + b₁ a₁₁ = 2·½·¼ = ¼ = b₁ b₁ = ¼` ✓
- `i=1, j=2`: `b₁ a₁₂ + b₂ a₂₁ = ½·(¼−√3/6) + ½·(¼+√3/6) = ½·½ = ¼ = b₁ b₂` ✓
- `i=j=2`: by symmetry, same as `i=j=1` ✓

**Order conditions**: 4th-order accuracy verified by the standard order-conditions tree for Runge-Kutta; `Σ b_i = 1` ✓.

Test asserts numerical Butcher-tableau entries to ≤1e-15 against the above closed-form values.

**State variables**: `(x^μ, p_μ)` canonical pair where `p_μ = g_μν(x) v^ν` is covariant momentum. At integrator input, convert from 4-velocity `v^ν` via Legendre transform. At output, optionally recover `v^ν = g^μν p_μ`.

*(Yoshida 1990 Ruth-4 coefficients removed; Ruth-4 is NOT symplectic for the non-separable geodesic Hamiltonian — see §2 decision #2 rationale.)*

### 5.4 SI-units sanity (Schwarzschild gotcha v0.4.0 caught)

`g_tt = −(1 − r_s/r) c²` in SI coordinates. Christoffel `Γ^r_tt` carries an extra `c²` factor versus the c=1 textbook form. v0.4.0 tests confirmed this (per `project_upt.md` line 29). v0.5.0 inherits the SI-aware Christoffel; Riemann and Ricci inherit the units automatically (no extra `c²` factor needed at the curvature level — units flow through). Validator does NOT enforce SI vs geometric units; tests use SI consistently.
