## Open question for the owner (requires user decision)

**Task 2 vs Task 13: when `wrt`-label collides with an existing free index in `of`, do we throw or warn?**

- **Adam's recommendation:** Drop the throw in Task 2; keep the warn in Task 13. Friendlier developer experience; lets non-strict code paths continue.
- **Eve's recommendation:** Keep the throw in Task 2; drop the warn in Task 13. Soundness > friendliness — the collision really does produce silently-wrong results, so it should be a hard error.

**My recommendation:** Eve's path. Christoffel/covariant-derivative semantics are unforgiving; silent wrongness is the worst failure mode. A throw with a clear "rename the free index" message is the right safety floor for v0.4.0. Add a future-version env-flag (`UPT_ALLOW_COORD_SHADOW=1`) if a relaxation is ever genuinely useful.

**Action:** await the user's call before applying fixes to Tasks 2 and 13.

The plan's MATHEMATICS is sound. The defects are entirely in implementation plumbing.
