# UPT v0.1.0 Release Procedure

A runbook for cutting the first tagged release when conditions are met.
Not a release announcement — that is composed at cut time from the
`## [Unreleased]` block in `CHANGELOG.md`.

## What v0.1.0 represents

The first tagged release of UPT marks the transition out of pre-formalization
to a stable scaffold. It does **not** mean the catalog is complete (it is
not), nor that all bridges are encoded as ASTs (most are unencodable in the
current scalar-AST scope and that is honestly recorded). It means:

1. The dimensional analyzer is sound and exhaustively covered: 240+ tests,
   `^` arity / switch-exhaustiveness / integral / derivative shape guards
   all in place; 22 named SI dimensions with round-trip `format()`.
2. The bridge index is correct, structured, and self-consistent: 40
   entries with dispositioned status, cross-field invariants enforced, the
   spec markdown and the index do not drift (`tests/bridges/spec-vs-index.test.ts`).
3. The encoded subset round-trips: every entry whose RHS lives in
   `src/bridges/equations/` validates back to its registered
   `dimensional_signature` via `tests/bridges/dimensional-signature-catalog.test.ts`.
4. The unencoded subset is classified, not hand-waved: see
   `docs/planning/Tier-5-Encoding-Triage.md` for the explicit reason each
   non-encoded bridge is non-encoded (operator algebra missing, tensor
   indices missing, R2 reformulation gap, R3 invalid, etc.).
5. Every R0/R1/R2 audit chain is closed; remaining R2 entries either have
   (a) a committed reformulation (BE-22 / BE-37 are the precedents — one
   reformulated, one R3'd) or (b) an explicit "domain expert needed"
   gap-record in their `notes`.

## Trigger conditions

Cut v0.1.0 when **any one** of these is true:

- **Encodable-subset coverage:** every entry classified `yes-ready` in the
  triage memo has an AST encoding. Current count: 7 of 8 yes-ready entries
  encoded (BE-19, 25, 26, 34, 41, 47, plus the BE-22 reformulation in
  progress; BE-40 was reclassified `no-r2-gap` mid-triage and does not count).
- **External publication trigger:** the project is published to npm /
  arXiv / similar. (Not currently planned but would force a tag.)
- **External-consumer trigger:** another project consumes
  `BRIDGE_EQUATIONS` or `validate()` programmatically. (Pre-formalization
  ends the moment someone else depends on the surface.)

If none of these is true, **stay on `[Unreleased]`**. There is no value to
cutting an artificial milestone for an unobserved library.

## Pre-cut checklist

Run from `master` with a clean working tree.

- [ ] `npm run build` clean (zero TypeScript errors).
- [ ] `npm test` clean (zero failures, zero skipped without justification).
- [ ] `tests/bridges/dimensional-signature-catalog.test.ts` covers every
      AST module under `src/bridges/equations/` (the test self-extends, so
      a green run is sufficient).
- [ ] `tests/bridges/spec-vs-index.test.ts` green: spec ↔ index has no drift.
- [ ] Every `## [Unreleased]` entry in `CHANGELOG.md` is accurate and
      reads top-down: `### Added`, `### Changed`, `### Fixed`, `### Removed`,
      `### Documentation`, `### Security` (Keep-a-Changelog order).
- [ ] No untracked files in `src/`, `tests/`, or `docs/`.
- [ ] `git log --oneline origin/master..HEAD` is empty (already pushed).
- [ ] `docs/planning/Tier-5-Encoding-Triage.md` reflects current state
      (re-run a triage scan if encoded count has changed since last update).

## The cut

Sequential atomic commits on `master` (no feature branch needed; this is
the release cut, not a development task):

1. **CHANGELOG**: rename `## [Unreleased]` to `## [0.1.0] - YYYY-MM-DD`
   (today's date in ISO 8601). Insert a fresh empty `## [Unreleased]`
   block above it.
2. **CHANGELOG header**: remove the "SemVer is not yet authoritative"
   block at the top. Replace with the standard Keep-a-Changelog header:
   ```markdown
   The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
   and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html)
   from v0.1.0 onward.
   ```
3. **`package.json`**: confirm `"version": "0.1.0"` (already set).
4. **README.md**: update the project status section if it mentions
   "pre-formalization."
5. Single atomic commit: `release: v0.1.0`. Body summarizes what v0.1.0
   represents (cribbed from this doc's "What v0.1.0 represents" section).
6. `git tag -a v0.1.0 -m "release: v0.1.0 — <one-line summary>"`.
7. `git push origin master && git push origin v0.1.0`.

## Post-cut tasks

- **GitHub release**: create a release on github.com/danielsimonjr/universal-physics-tensor
  pointing at the `v0.1.0` tag. Body = the `## [0.1.0]` section of CHANGELOG
  (a judgement call whether to include the full Wave F + Tier-5 detail or
  summarize).
- **Update the CHANGELOG header** — once v0.1.0 is cut, the SemVer carve-out
  no longer applies; subsequent breaking changes go to v0.2.0 (minor bump
  for breaking pre-1.0 is acceptable per SemVer §4: "Anything MAY change
  at any time. The public API SHOULD NOT be considered stable.").
- **Triage memo** gets a final pass: anything previously deferred to "Wave 2
  AST extension" gets a fresh decision (extend the AST or accept as a
  permanent gap).
- **Open an issue** for the next milestone (v0.2.0): pick scope (more
  encodings, AST extension for one cluster, application-side work for the
  visualization-engine repo, etc.).

## What NOT to do at cut

- Do **not** cut v0.1.0 because `package.json` already reads `0.1.0`. That
  is bureaucratic momentum, not a release.
- Do **not** cut v0.1.0 to "establish a baseline." Master commit hashes
  are baselines; tags are public commitments.
- Do **not** include unfinished work in the v0.1.0 changelog block. If a
  feature is half-done, leave it in `## [Unreleased]` and cut without it.
- Do **not** force-push a tag. Tags are immutable once pushed; if v0.1.0
  is wrong, cut v0.1.1.
- Do **not** rewrite `CHANGELOG.md` history (the prior `## [Unreleased]`
  entries are now the v0.1.0 entries; do not edit them).

## Readiness

Status and dates for this document are in `NOTES.md` and `CHANGELOG.md`. The readiness measured when this
procedure was written (coverage, test count, dispositions, trigger conditions) was moved
there; this file keeps the procedure.

The decision to cut v0.1.0 now is the user's. The mechanical readiness is
in place; the question is whether to mark this stable or accumulate more
in `[Unreleased]` until the next milestone (e.g., another R2 reformulation
landing, or AST primitive work beginning).
