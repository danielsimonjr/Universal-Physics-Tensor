# Theoretical physics (GR / QFT) — CLI dogfood, 2026-09-29

Session on master `44e4450`, same install as the applied-physicist report. The command used for curvature is `upt metric` (alias `curvature`). Signature on every metric printed here is `(−,+,+,+)`, and the note says that is the canonical Einstein-equation metric node.

## What worked

- Schwarzschild at the solar default, `upt metric schwarzschild`. `r = 10` geometric masses (`r ≈ 29541 m`, horizon `≈ 2954 m`). Kretschmann matches the closed form `48 G² M² / (c⁴ r⁶)` to the digits the finite difference holds (`1.575668422e-19` against `1.575668525e-19` on that run). Christoffel matches the textbook components that were checked, including `Γ^r_tt` of order `1e11` and `Γ^r_θθ = −(r − r_s)`.
- Minkowski prints Ricci and Kretschmann as 0, no Christoffel symbols, and says the angular block is not a sphere (`g_θθ = g_φφ = 1`).
- Kerr geodesics run. `upt metric kerr a=1000 r=2e4 --geodesic` is a spin `a/M ≈ 0.68` and exits 0. `a = 0` is the Schwarzschild limit and must not warn. Help already says `θ = π/2` is equatorial and any other `θ` is an inclined spherical orbit.
- The Compton convention line, the Einstein `8π` check, and the perihelion factor `one_minus_e_sq` behaved as the earlier GR dogfood recorded. Those were not re-broken. A bare `e` in a Bohr-radius formula is still exit 2.
- `upt eval --json` of a scalar is one envelope a script can parse. After this branch the ħ note is in `result.notes` as well as on stderr.

QFT-specific surface used from this seat: Compton wavelength (both conventions), rest energy, and the Klein–Gordon → Schrödinger route. The route itself is in the engineering report. There is no mode expansion, no spinor, and no Dirac equation on this CLI. That is a missing command, not a wrong answer.

## Bugs

### Vacuum Ricci noise is printed as Ricci, and curved FLRW prints the finite-difference residual

```
upt metric schwarzschild
```

Printed `R_tt ≈ 0.018` and `ricciScalar ≈ 1.5e-17` beside `closedForm.ricciScalar = 0`. The closed form is the vacuum result. The finite-difference residual was listed because its own scale is the cutoff `nonzeroMatrix` uses.

```
upt metric kerr a=0.9
```

Kerr is vacuum. Printed a Ricci component of order `1e-8`.

```
upt metric flrw k=1 t=2 rho=0 Lambda=0
```

Printed `ricciScalar ≈ 3e-17` and `closedForm.ricciScalar = 2.381…`. The finite difference is taken at `c = 1` and then divided by `c²`, which drops the spatial-curvature piece `6k/a²`. The headline scalar was the residual. `H²` and the Friedmann right-hand side differed (`0.111` against about `−3.6e16`) and the command did not say the scale factor is not a solution. `k = 1` with `c` in m/s is a curvature radius of about a metre, not the dimensionless `k = ±1` of geometrized cosmology.

Expected: when the closed-form Ricci scalar is 0 and the residual is below `1e-6`, the report says Ricci is 0 and does not list the residual. When the finite-difference scalar disagrees with a nonzero closed form, the headline scalar is the closed form and the note says why the `1/c²` restoration dropped spatial curvature. When `H²` and the Friedmann right-hand side disagree, the note says this scale factor is not a solution, and what `k = 1` means in SI. Fixed on this branch. A flat-dust FLRW run whose finite difference already matches `3 H²/c²` is left on that difference.

### Kerr `a = 0.9` is not a spin, and `a/M` is not printed

```
upt metric kerr a=0.9
```

Default mass is the Sun. `M_geom ≈ 1477 m`. `a = 0.9` is 0.9 metres, so `a/M ≈ 6.1e-4`, a Schwarzschild orbit with a rounding of spin. The parameters line did not print `a/M`. The help example `a=1000` (with a large enough `r`) is the order of a real spin; `a=0.9` looks like the dimensionless spin people type.

`upt metric kerr a=0.9 M=1` exits 2 with `Kerr finite difference wants |a| < r`, because `M = 1` kg makes `GM/c²` tiny. That refusal is correct. It does not explain that `a` was read as a length.

Expected: parameters include `a_over_M`, and a warning when `|a| ≤ 1` metre on a geometric mass above 10 m, so a solar-mass `a=0.9` is called a length. `a = 0` does not warn. `|a| > 1` (the `a=1000` example) does not warn. Fixed on this branch. Help states that `a` is a length and that the report prints `a/M`.

## Confusing UX and docs

- `upt metric schwarzschild M=1Msun` and `upt metric kerr theta=pi/2` both exit 2 with `not a finite number`. `upt eval` accepts `1Msun` and `pi`. The curvature command does not. A user who just computed a solar mass pastes `M=1Msun` and gets a parser error.
- The FLRW help line says the finite difference is restored with `1/c²`. It did not say that this restoration is wrong for `k ≠ 0`, which is how the residual became the headline. The note on the report now says that, for the run that disagrees.
- Kerr `--geodesic` with `a=0.9` and the solar mass exits 0 and integrates an orbit. Before this branch that orbit was essentially Schwarzschild and the text did not say so. The warning is now on the report; the integrator still uses the length you passed.

## Suggestions not implemented

- Accept `M=1Msun` and `theta=pi/2` on `upt metric`, with the same unit and constant reading `upt eval` uses. Left open. The finite-number parser is what rejected them; this branch does not change it.
- A dimensionless spin flag (`a/M` as an input) would remove the metre trap. Not added. The warning and `a_over_M` are the disclosure; a second way to pass `a` is a design change.
